## 二、轮子提取：做了什么、为什么

### 2.1 `askConfirm` —— 把只做了一半的轮子做完

这是本轮的核心。发现过程值得记下来：

项目里**已经有** `askText`（Promise 化的输入框），实现方式是 zustand store + Host 组件 + `new Promise`，很干净。但同一个项目里，确认框却在 33 个地方继续调原生 `window.confirm`。

也就是说，这个轮子只做了一半 —— 输入框收编了，确认框漏了。

原生 `window.confirm` 的三个实际问题：

1. **长得不像这个程序。** 系统灰底、按钮顺序随 Windows 版本变，用户会犹豫「这是日签在问我吗」。
2. **阻塞整个渲染进程。** confirm 挂着的时候界面是死的：动画停、滚动停、输入框进不去。
3. **没法带样式。** 想强调「删了就找不回来了」只能靠文字加感叹号；真正该做的是把按钮染成红色、让「取消」拿到焦点。

**实现**（`components/ui.tsx`）：完全照抄 `askText` 的范式，保证两个弹窗共用同一套 `Dialog` 骨架。

```tsx
export const askConfirm = (title: string, opt?: ConfirmOpt) =>
  useConfirmStore.getState().ask(title, opt);
// 用法：if (!(await askConfirm('删掉这条？', { ok: '删掉' }))) return;
```

**三个设计取舍：**

**① 危险与否不靠猜关键字，靠调用方说。** 传了 `ok` 才算危险操作。如果去匹配「删除/清空」这些字，迟早会猜错 —— 猜错的两种后果都难看：「删除」按钮不是红的，或者「关闭」被误染成红的。

**② 「取消」自动获得焦点。** 手快按回车不能等于删除。

**③ 多行文案自动拆成标题 + 正文。** 老代码里大量这种写法：

```js
confirm('把「早起」移到回收站？\n打卡记录会保留，可以在回收站里恢复。')
```

整段塞进 `<h3>` 的话，第二行会跟着标题一起变大变粗，读起来像两句口号。所以 `ask` 里自动按第一个 `\n` 切分：首行进标题，余下进正文。**这样迁移时一个字都不用改，版式自动就对了。**

**迁移 31 处的做法**：写脚本逐条替换（`tests/_migrate_confirm.py`），每处补上准确的按钮文案。其中 2 处原本在同步函数里（`draw.tsx` 的 Esc 处理和 `clearAll`），改成 `async` 并给事件监听包一层 `void`。

**顺手补的样式**（`styles.css`）：

```css
.btn.primary.danger{background:var(--bad);border-color:var(--bad);color:#fff}
.cfm-body{font-size:13.5px;line-height:1.85;color:var(--ink2);white-space:pre-line}
```

`.btn.primary.danger` 必须写在 `.btn.primary` 之后 —— 否则危险按钮会被蓝色主按钮盖掉。**危险的按钮长成普通按钮的样子，才是真危险。**

### 2.2 `ColorDots` —— 24×24 圆形色板

原来在 4 个文件里手写了 5 遍。其中 `features/notes.tsx` 一个文件里就有 2 遍，而且正是用户抱怨「笔记本弹窗界面好粗糙」的那个地方。

收成组件后保留三个变体参数（`title` / `boxSizing` / `size`），**没有强行统一** —— 那 4px 的 `border-box` 差异是真实存在的（不加的话选中态会把布局挤动 4px），统一了就是新 BUG。

替换 6 处：`notes.tsx` × 4、`todos.tsx` × 1、`Habits.tsx` × 1。

### 2.3 `EmptyState` —— 空态

104 处 `<div className="empty">`，其中 8 处各自用内联 style 打补丁（跨网格、居中变淡、调行高），于是同一个「空态」在不同页面上有四种长相。

收成组件后那几种差异变成三个明确属性：`grid` / `center` / `small`。**这一轮只换了那 8 处特殊的**，其余 96 处保持原样 —— 机械替换 96 处收益很低，风险不为零，留着以后顺手改。

顺手清掉一个真实隐患：`.empty` 在 `styles.css` 里定义了两次（第 884 行和第 2828 行），后者覆盖前者的一半。两处隔了 2000 行，改一处忘一处。已把颜色/字号并进末尾那一处，删掉前面那条。

### `verify-confirm.js` 验的是什么

不是「弹窗能弹出来」，而是四个真会出事的地方：

```
标题 = "把「阅读」移到回收站？"
正文 = "打卡记录会保留，可以在回收站里恢复。"     ← \n 已正确拆成正文
按钮 = [{"t":"取消",cls:"btn"},
        {"t":"移到回收站",cls:"btn primary danger","bg":"rgb(179,72,63)"}]
✅ 点取消后数据一条没动  卡片 4 → 4              ← 最容易搞反的语义
✅ 点确认后真的执行了（卡片数变少）  4 → 3
✅ 全程没有出现原生 window.confirm                ← 装了 dialog 监听器，漏网就报错
✅ 已把 1 个打卡还原  阅读                        ← 跑完自己收拾
```

探针自带还原：第 3 步确实删了一个打卡，结束时从回收站还原回去。**不还原的探针会污染用户数据**，第一次跑完「阅读」就留在了回收站里。

### `verify-empty.js` 验的是什么

抽组件最大的风险不是"渲染不出来"，而是**样式悄悄变了** —— 漏一个 padding、少一个 border、`gridColumn` 没生效，页面还是能跑、探针还是绿的，但界面已经歪了。所以逐项比对计算样式：

```
{"borderStyle":"dashed","borderRadius":"10px","fontSize":"13.5px","hasBg":true}
✅ 虚线边框还在 / 圆角还在 / 浅底还在 / 字号 13.5px 保住了
✅ small 内边距小于默认 16px   10px 12px
✅ center 形态样式确实生效（居中 + 变淡 + 上边距 24px）
```

## 六、踩过的坑（写下来免得下次再踩）

**① 探针"跳过"不等于通过。** `verify-empty.js` 第一版去媒体库找空态，结果库里有内容，一段判成「不为空，跳过」—— 绿了但什么都没测。改成主动搜索一个不存在的词**强制造出空态**。测空态就得先把数据弄空。

**② 探针的判据本身可能是错的。** 第一版断言「空态必须 `gridColumn:1/-1`」，媒体库那段报了红。查下来 `.mlist` 是 `display:flex`，本来就不需要跨列 —— 是我判据错了，不是代码错了。改成「父容器是 grid 时才要求跨列」。

**③ 直接 remove DOM 节点会让 React 状态失同步。** 探针开头想清掉别的探针留下的弹层，写了 `document.querySelectorAll('.mask').forEach(m=>m.remove())`。结果遮罩没了但 store 还认为弹窗开着，之后**整个页面点哪都没反应**，打卡页变成 0 张卡片。正确做法是整页 `reload`。

**④ 别在跑测试时删用户真实数据。** 前面提过，`verify-confirm.js` 第一次跑完把「阅读」留在了回收站。已补还原逻辑，并验证了连跑两次数据不变。

## 七、如果还要再往下走

这一轮验证了一件事：**这个项目的问题不是重复代码多，是超长函数。**

- `LedgerView` 单函数 1516 行、37 个 useState，内部靠 6 条注释切块，边界只活在注释里
- `Settings.tsx` 2284 行、15 个组件

这些才是真正该动的，但那是**重构**不是**精简** —— 必须改 DOM 结构、要重写 9 个依赖 `.lg-*` / `.kpi` 选择器的探针、要逐块回归。

拆分方案和约束条件写在 `docs/组件化审计报告.md`。

**剩下的候选轮子**：`StatCard`（31 处 `.kpi` 结构相同，但内容差异较大，抽了会变成一堆 props）、`useSetting`（146 处 `setSetting`，其中 52 处是 `=== '1'` 的布尔套壳，这个确实值得抽）。

**结论：本轮到此为止。** 继续下去的收益是代码可读性，代价是回归成本，应该作为独立一轮做。
