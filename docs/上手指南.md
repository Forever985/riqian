## 0. 三十秒认识它

日签是一个 Windows 单机日记 + 打卡应用。没有服务器，没有账号，数据是本地一个 SQLite 文件。

```
C# WinForms 宿主 (WebView2)  ──  前端 React 18 + TypeScript
        │                              │
        │  postMessage RPC             │  api.ts 封装
        └──────────  230 个方法  ───────┘
                       │
                  SQLite 单文件
```

一句话技术栈：**WinForms 装壳，React 做界面，230 个 RPC 当 API，SQLite 存数据。**

## 1. 五分钟跑起来

### 1.1 环境

| 需要 | 版本 | 检查 |
|---|---|---|
| .NET SDK | 8.0+ | `dotnet --version` |
| Node.js | 18+ | `node -v` |
| WebView2 Runtime | 任意较新版 | Win10/11 一般自带 |

### 1.2 构建

```bash
# 1) 先构建前端（产物要嵌进 exe，顺序不能反）
cd web
npm install
npm run build          # 输出 web/dist 和 wwwroot/index.html

# 2) 再构建 C#
cd ..
dotnet build -c Debug
```

产物：`bin/Debug/net8.0-windows/日签.exe`

> ⚠️ **改前端之后必须 `npm run build` 再 `dotnet build`。**
> `wwwroot/index.html` 是 `<EmbeddedResource>`，C# 编译时才打进 exe。
> 只改 TS 不重新 build，跑起来看到的还是旧界面 —— 这个坑人人踩一次。

### 1.3 跑

```bash
./bin/Debug/net8.0-windows/日签.exe
```

数据默认在 `%LOCALAPPDATA%\Riqian\`（可在设置里改）。
日志在 `%LOCALAPPDATA%\Riqian\logs\YYYY-MM-DD.log`。

### 2.3 RPC 是怎么串起来的

```
前端   api.entrySave({date, values})
         ↓  rpc('entry.save', {...})
       postMessage({ id, m: 'entry.save', a: {...} })
         ↓
宿主   MainForm.OnMessage → Dispatch(m, a)
         ↓  V10Dispatch → V9Dispatch → V8Dispatch → V7Dispatch → 主 switch
      db.EntrySave(...)
         ↓
前端   { id, ok: true, data: {...} }  →  Promise resolve
```

**关键点：`Dispatch` 是五段拼起来的。** 加新方法时随便放哪一段都行，
但**同一个方法名不要在两段里都写** —— 排前面的先命中，后面那段永远不执行，
而且极难查。

## 3. 加一个 RPC 接口（最常见的任务）

假设要加 `foo.bar`，参数 `{id, note}`，返回 `{ok}`。

### 3.1 后端

1. 在 `Db.cs` 里写实际逻辑：

```csharp
public object FooBar(string id, string note)
{
    Exec("UPDATE foo SET note=$n WHERE id=$id", ("$n", note), ("$id", id));
    Touch();
    return new { ok = true };
}
```

> `Exec()` 返回 `void`；要取行用 `Rows()`，第二个参数必须是
> `(string k, object v)[]` 具名元组数组，别传匿名对象。

2. 在 `MainFormV10.cs` 的 `V10Dispatch` 里挂上：

```csharp
if (m == "foo.bar") return db.FooBar(S(a, "id"), S(a, "note", ""));
```

3. 在 `RpcCatalog.cs` 的 `All` 数组里登记（否则 SelfCheck 会 WARN）：

```csharp
M("foo.bar", "杂项", "改一条 foo 的备注", "id, note", true),
```

4. 重新生成方法清单：

```bash
python tools/gen-rpc-list.py
```

### 3.2 前端

在 `web/src/api.ts` 里加封装：

```ts
fooBar: (id: string, note: string) => rpc<{ ok: boolean }>('foo.bar', { id, note }),
```

然后在组件里 `await api.fooBar(id, note)`。

### 3.3 验证

```bash
cd web && npx tsc --noEmit     # 类型
cd .. && dotnet build -c Debug  # 编译
```

跑起来在控制台里试：

```js
window.chrome.webview.postMessage({ id: 1, m: 'foo.bar', a: { id: 'x', note: 'hi' } })
```

或者用 AI 网关（见 §4）直接 `curl`。

## 4. 用 AI 调试网关（排障神器）

### 4.1 开启

```bash
日签.exe --debug-api              # 随机端口
日签.exe --debug-api=57100        # 指定端口
```

或：设置 → 数据 → 诊断日志 → 展开 → AI 调试接口 → 开启。

开启后连接信息写在 `%APPDATA%\Riqian\debug-api.json`。**整份文件交给 AI 即可。**

### 4.2 用法

```bash
TOKEN=$(node -e "console.log(require(process.env.APPDATA+'/Riqian/debug-api.json').token)")
PORT=$(node -e "console.log(require(process.env.APPDATA+'/Riqian/debug-api.json').port)")

# 探活（唯一不用 token 的）
curl http://127.0.0.1:$PORT/health

# 问它有哪些能力 —— 不用翻文档
curl -H "X-Token: $TOKEN" http://127.0.0.1:$PORT/methods

# 查某个方法怎么调
curl -H "X-Token: $TOKEN" "http://127.0.0.1:$PORT/method?name=entry.save"

# 真的调一个
curl -X POST -H "X-Token: $TOKEN" -H "Content-Type: application/json" \
     -d '{"m":"bootstrap","a":{}}' http://127.0.0.1:$PORT/rpc

# 读日志
curl -H "X-Token: $TOKEN" "http://127.0.0.1:$PORT/logs?lines=100"
```

> Windows 上如果 curl 走代理导致连不上，加 `--noproxy 127.0.0.1`。

### 4.3 边界（别搞错）

- **默认关闭**，必须显式开。
- 只绑 `127.0.0.1`，**局域网连不进来**。
- 每次启动 token 重新生成。
- 所有调用串行到 UI 线程 —— 因为数据库是单连接且无锁，并发会写坏库。

## 5. 排障流程

### 5.1 用户说「出错了」，按这个顺序

1. **让他打开 设置 → 数据 → 诊断日志**，点「只看问题」，然后「复制」发给你。
   这一条能解决 80% 的问题，因为里面有完整堆栈、方法名、参数（已脱敏）。
2. 需要更多细节时，让他把「记录级别」临时调到 **Trace**，复现一次再调回 Info。
3. 还不行就看 `%LOCALAPPDATA%\Riqian\logs\<日期>.log` 原始文件。

### 5.2 日志怎么读

```
2026-11-01 21:14:37.058 ERR rpc | 方法 entry.save 执行失败 · 耗时 12ms · 参数 {"date":"..."}
  ✗ System.InvalidOperationException: ...
      at Riqian.MainForm.Dispatch(...)
    ↳ System.IO.IOException: 真正的原因在这
```

- `ERR rpc` → RPC 层捕获的异常，后面跟着方法名和参数
- `WRN rpc` + `慢调用` → 某个操作超过 800ms，界面发卡的直接证据
- `INF boot` / `FTL boot` → 启动阶段
- `ERR js.*` → 前端上报的问题（`js.react.boundary` 是渲染崩了）

### 5.3 启动就崩（连界面都出不来）

看 `%TEMP%\riqian-boot-error.log`。这是独立于主日志系统的兜底通道，
专门用在「日志系统自己都没起来」的场景。

```bash

# 另开一个终端
```

**不用每次跑全量。** 只测「改动的那部分 + 受影响的那部分」就行，

## 7. 几条硬规矩（血泪教训）

### 7.1 绝对不要改回 `NavigateToString`

它有 2 MB 上限（UTF-16 字符计）。页面已经 3 MB，改回去必定启动失败。
用 `HtmlHost` 的虚拟主机映射。

### 7.2 数据库只能在一个线程上用

`Db` 用的是单个 `SqliteConnection` 且**没有加锁**。
任何从非 UI 线程来的调用都必须 `Control.Invoke` 搬回主线程。
`DebugApi.RunOnUi()` 就是干这个的。

### 7.3 `ModuleValue` 不接受对象

```ts
type ModuleValue = string | number | string[] | QuoteRef[] | null;
```

想存结构化数据就 `JSON.stringify` 成字符串。

### 7.4 日志里不许出现秘密

新模块的参数里如果有密码、答案、密钥：
把方法前缀加进 `Diag.SecretMethodPrefixes`。**别指望字段名匹配** ——
密保答案的参数名就是 `a`，字段名校验抓不到。

### 7.5 发布前问用户

构建 ≠ 发布。`dotnet publish` 和覆盖安装目录里的 exe 都要先问。

### 7.6 每次改动都要留痕

- `.workbuddy/memory/YYYY-MM-DD.md` —— 开发日志
- `web/src/lib/changelog.ts` —— 给用户看的更新日志
- `开发文档.md` —— 追加一节 `## N. vX.Y：标题`

半年后没人记得某个设计为什么是这样。**写下来，否则等于没做。**

## 9. 出问题找谁

先看 `%LOCALAPPDATA%\Riqian\logs\` 今天的日志。
日志里没有的话，那就是日志系统本身的问题 —— 看 `Diag.WriteFailures` 计数
（设置 → 诊断日志的统计条里有「写盘失败」一格）。
它非 0 说明磁盘满、权限不对，或者杀毒软件在拦截。
