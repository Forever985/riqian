## 二、这轮修掉的三个真 bug

### ① `notebooks.list` 漏返回 `parentId`（**高**，本轮最重要）

- **文件**：`DbV7.cs` → `Notebooks()`
- **现象**：笔记本层级功能整体不生效 —— 子本不缩进、折叠箭头不出现、
  跨层拖动没反应、`MoveNoteDialog` 分组全平。
- **根因**：接口只返回 `id/name/color/sort/count`，漏了 `parentId`。
  前端第 220 条起整条链路全建在 `b.parentId` 上，`undefined` 让每个本都被当顶层。
  **数据库里 `parent_id` 是对的** —— 数据对、显示错。
- **修法**：`parentId = r.ContainsKey("parent_id") ? Str(r["parent_id"]) : ""`
- **为什么必须 `ContainsKey`**：`Db.Rows()` 返回 `Dictionary`，**取不存在的键抛异常**。
  老库没跑过 `EnsureV10` 就没这列，直接索引会让整个接口 500。
- **已探针实测**：9/9 条都带 `parentId`，3 条子本 / 6 条顶层。

### ② 全新安装后记账本整页报 `no such column: jar_id`（**高**）

- **文件**：`Db.cs` 启动迁移链 / `DbV13.cs`
- **根因**：迁移链只跑到 `EnsureV11()`，漏了 `EnsureV13()`（`jar_id` 列在这里 EnsureColumn）。
- **修法**：迁移链末尾补 `EnsureV13()`；`EnsureV13` 从 `private` 改 `internal`，懒调用保留（幂等）。
- **特点**：只打新用户，老库被历史掩盖。

### ③ 支出堆叠图整块消失，控制台刷 NaN（中）

- **文件**：`DbV11.cs` 的 `CatPart` / `LedgerCharts.tsx`
- **根因**：`cat`/`sum` 写成 **public 字段**，`System.Text.Json` 默认不序列化字段 →
  前端拿 `undefined` → `undefined <= 0` 是 `false`，绕过拦截 → 坐标 NaN → 整图被丢。
- **修法**：改属性 + 前端加 `Number.isFinite` 兜底。

（另有第四个：笔记页左右两列不等高，`align-items:start` → `stretch`，已修。）

## 五、下次开工要注意的（血的教训）

1. **`Db.Rows()` 取不存在的键会抛异常**，不是返回 null。新加列一律 `ContainsKey`。
2. **改任何 `xxx.list` 都要对照 `RpcCatalog` 的字段说明核一遍** —— 少返回一个字段
   可能让整片功能"消失"，而数据完全正确。
3. **RPC 写操作一律单数**（`todo.delete` / `note.purge` / `notebook.delete`），
   复数只用于列表查询。写错返回「未知方法」，**不报错也不生效**。
4. **清理脚本必须逐个断言返回值**，且**自底向上删**（先子后父）。
   已修 `verify-view-refactor.js` 第 8 段（改完只做了 `node --check`，还没实跑）。
5. **测试数据必须包含被测特性的结构** —— 用平铺数据测树形功能，测的是最不容易出错的场景。
6. 完整 `dotnet build` 会失败：exe 被用户正在跑的实例锁着。
   **不要 `taskkill` 用户的程序**，用 `dotnet build -t:Compile` 即可。
