### 6.3 这轮的关键技术决定

**字体为什么不用 `@font-face` 而用 `FontFace`。**
页面 origin 是 `https://riqian-app.example`（`HtmlHost.Host`），字体文件在 `<数据根>/字体/`，
两者不同源。`@font-face { src: url(...) }` 跨 origin 拉字体要过 CORS，而 WebView2 的
`SetVirtualHostNameToFolderMapping` 不发这个头。`FontFace` 吃 `ArrayBuffer`，完全不走网络，
绕开了整件事 —— 代价是文件字节要经一次进程内消息（单文件上限设 64 MB）。

**为什么存 `<数据根>/字体/` 而不是塞进多媒体库。**
多媒体库那套有缩略图、内容哈希去重、软删除、回收站，字体只有「在不在」两种状态，
套进来全是负担。和图片库平级放一个独立目录，`font.list` 直接扫文件名就够了。

**`monthly-weekday` 为什么挤在 `repeat` 字段里而不是加两列。**
加 `nth` + `weekday` 两列意味着改表 + 4 处迁移 + 所有读 repeat 的地方都要看有没有这两列。
编成 `"monthly-weekday:-1:4"` 一行字符串，旧数据完全不受影响，前后端解析规则各自
写在 `repeatCode()` 和 `Db.Countdowns()` 里。代价是这俩必须保持一致 —— 单测 `unit-192.js`
就是钉这个的（41 项）。

内置主题表是编译进代码的常量，运行时加不进去；而 `themeCustom` 本来就是

### 7.3 踩到的两个真问题

**① `normalizeTheme` 吃掉 `pack:` 前缀 → 装了主题毫无反应**

初版 `normalizeTheme` 对所有不在 `THEMES` 里的键一律回退到 `paper`。
于是 `settings.theme = 'pack:probe.dusk'` 存进去了，但 `applyAppearance` 读的是
normalize 之后的名字，永远拿 `paper`，`themeCustom['pack:xxx']` 那一条永远取不到。
**探针实测：点完安装 `--bg` 仍是 `#f4f1e9`，完全没有变化。**

修法：`normalizeTheme` 原样保留 `pack:` 前缀。此时 `html.dataset.theme="pack:xxx"`，
CSS 里没有这个选择器，变量落到 `:root/paper` 那套出厂值；紧接着 applyAppearance
用内联 style 覆盖成包里那 16 色（内联优先级最高）。这正是"覆盖"该有的顺序。

**② 拖色相条看不出变化**

画板默认笔色 `#1f1c18`，明度只有 0.12。只拖色相 → 得到 `#1c181f`，肉眼还是黑。
用户会以为拾色器坏了。修法：拖色相条时给明度和饱和度一个 0.55 的下限，
只在拖色相时兜底，拖饱和度/明度面板时不动。

### 8.3 这轮踩的坑

**① `Timer` 二义性（CS0104）。** `Sticky.cs` 里有 `using System.Threading`（间接引入），
`Timer` 在 `System.Windows.Forms` 和 `System.Threading` 下各有一个。报错信息只说「有歧义」，
不说该选哪个。修法：写全名 `System.Windows.Forms.Timer`。

**② 自定义 `Load(...)` 隐藏 `Form.Load` 事件（CS0108）。** 本来给 `StickyForm` 写了个
`Load(MainForm, string)` 当初始化入口，编译器警告它把基类的 `Load` 事件挡住了。
加 `new` 能压掉警告，但之后谁写 `form.Load += ...` 就会静默失效。改名 `LoadNote(...)` 更干净。

**③ 独立 `Form` 拿不到 `MainForm.db`（CS0122）。** `db` 是 `private`。`StickyForm` 不是
`MainForm` 的内部类，访问不到。修法：在 `MainForm` 上开 `internal` 只读口子
`StickyNoteGet` / `StickyMeta` / `StickyMetaSet` / `StickyCount`，把能力收窄到「便签需要的这四件」，
而不是把整个 `db` 暴露出去。

**④ `Icon.FromHandle` 的 HICON 要自己销毁。** `WithLockBadge` 里
`var h = bmp.GetHicon();` 出来的 HICON 归调用方所有，不 `DestroyIcon` 就是漏 GDI 句柄，
托盘图标每换一次漏一个。

```csharp
var h = bmp.GetHicon();
try { using var tmp = Icon.FromHandle(h); return (Icon)tmp.Clone(); }
finally { DestroyIcon(h); }
```

**⑤ 数据库新列必须加在 `MigrateIdsToText()` 之后。** 该方法会整表重建，
新加的列如果在它之前 `ALTER`，重建时会被吃掉。

**#87 幽灵按钮**

用户点名：「在"联系我们"中，"用模板"这个按钮没有体现出是个按钮。」

根因不是颜色深浅，是**边框根本没画出来**：
`border-color: color-mix(in srgb, var(--ink) 8%, transparent)` ——
8% 的墨色算出来是 `rgba(38,34,29,.08)`，浅色主题下肉眼看不见，深色主题直接沉底。
于是 ghost 按钮只剩一团 `--ink2` 的字，跟旁边的说明文字长得一模一样。

改两层：边框提到 **18%**（跟 `--line` 同一量级，是"有边"的最低可感知线），

深色主题不用另写 —— `var(--ink)` 本来就跟着主题反色。

**顺手清掉一个隐藏冲突**：第 2142 行还有一条
`.btn.ghost:hover{background:var(--panel2);border-color:var(--line)}`，
靠源码顺序把 `:hover` 的 accent 边框整个盖掉 —— 悬停时反而比静默态更灰。已删。

实测：静默态边框 `0.18` + 底色 `0.03` + 圆角 7px + `cursor:pointer`；

### 14.6 CI 配置本身还差什么

本地跑通了，但真上 GitHub 之前还有几处要改：

1. **`dotnet publish` 没有 `--no-restore`**，会重复还原一次（慢几秒，无害）；
2. **上传产物只传 `Riqian.exe`**，而 `publish/` 里还有三个 `Microsoft.Web.WebView2.*.xml`
   （约 800 KB 文档），不传也无所谓，但 `SingleFile` 之外若产生附属 dll 就会漏；
3. **没有缓存 NuGet 包**，每次 CI 全量下载（可用 `actions/cache`）；
4. **体积阈值 4 MB 与项目自定的 2 MB 不一致** —— 注释里说「2 MB 是 NavigateToString
   时代的历史约束，现在放宽到 4 MB」，但 MEMORY 和交接文档都写「上限 2 MB」。
   现在实际 1.48 MB，两档都过，暂时不影响；等真逼近时得先统一口径。
5. **最长的那条没跑**：CI 不启动 exe、不跑任何探针。上面抓到的两个 bug 都是
   「启动后」才现形的 —— 如果 CI 只跑到 publish 就结束，这两个 bug 会一直藏着。
   **建议后续加一步**：publish 后以 `--debug-api=<port>` 起进程，
   拉 `/health`、跑一遍只读接口再杀进程。这是本轮最值得回灌到 CI 的一条。
