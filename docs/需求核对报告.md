### 5.4 本轮新发现并修掉的 bug

- **统计「按月的字数」标签错**：`monthWords` 的 `m` 是 `2026-10`，原来走 `fmtMonthDay(\`${m}-01\`)` 渲染成「10月1日」。
  月份序列不该有「日」。新增 `fmtYearMonth()` 专门处理年月，`Stats.tsx` 改用它。
- **总结页 3 处硬拼日期**：`${m} 月 ${d} 日` 写死空格分隔，不跟语言也不跟顺序。全部改用 `fmtDate()`。
- **`cnDateLabel` 写死「M月D日」**：改为按 `DATE_FMT` 拆顺序，但仍不带年份（它原本就是短标签，补年份会撑爆一行）。

### 5.5 新增的「年月日顺序」设置（#106 补全）

### 6.3 这轮的关键技术决定

**字体为什么不用 `@font-face` 而用 `FontFace`。**
页面 origin 是 `https://riqian-app.example`（`HtmlHost.Host`），字体文件在 `<数据根>/字体/`，
两者不同源。`@font-face { src: url(...) }` 跨 origin 拉字体要过 CORS，而 WebView2 的
`SetVirtualHostNameToFolderMapping` 不发这个头。`FontFace` 吃 `ArrayBuffer`，完全不走网络，
绕开了整件事 —— 代价是文件字节要经一次进程内消息（单文件上限设 64 MB）。

**为什么存 `<数据根>/字体/` 而不是塞进多媒体库。**
多媒体库那套有缩略图、内容哈希去重、软删除、回收站，字体只有「在不在」两种状态，
套进来全是负担。和图片库平级放一个独立目录，`font.list` 直接扫文件名就够了。

**`monthly-weekday` 为什么挤在 `repeat` 字段里而不是加两列。**
加 `nth` + `weekday` 两列意味着改表 + 4 处迁移 + 所有读 repeat 的地方都要看有没有这两列。
编成 `"monthly-weekday:-1:4"` 一行字符串，旧数据完全不受影响，前后端解析规则各自
写在 `repeatCode()` 和 `Db.Countdowns()` 里。代价是这俩必须保持一致 —— 单测 `unit-192.js`
就是钉这个的（41 项）。
